# Хмарний голосовий помічник

Навчальний проєкт для автоматизації обліку постачальників, товарів і поставок за допомогою вебінтерфейсу, Telegram-бота та голосових команд.

## Поточна архітектура

- **FastAPI** — єдиний серверний застосунок і REST API.
- **PostgreSQL** — основна база даних.
- **SQLAlchemy** — робота з таблицями та зв'язками.
- **Вебінтерфейс** — україномовна панель для ведення довідників і реєстрації поставок.
- **Telegram** — webhook використовує ті самі серверні сервіси; підтримує текстові й голосові повідомлення, розпізнавання українського мовлення та голосову відповідь.
- **Голосові функції** — наступний етап: завантаження аудіо, розпізнавання українського мовлення та синтез відповіді.

## Структура

```text
backend/
  api/routes.py          REST-операції
  database/               моделі, підключення та схема БД
  config.py               налаштування через змінні середовища
  main.py                 точка запуску FastAPI
frontend/
  index.html              вебсторінка
  style.css               оформлення
  app.js                  взаємодія з API
tests/
  test_api.py             автоматизовані тести API
```

## Локальний запуск у Windows

Потрібні Python 3.11 або новіший та встановлений PostgreSQL.

1. Клонувати репозиторій і перейти в його каталог.
2. Створити віртуальне середовище:

   ```powershell
   py -m venv .venv
   .venv\Scripts\activate
   ```

3. Встановити залежності:

   ```powershell
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

4. Створити в PostgreSQL базу даних з назвою `voice_assistant`.
5. Скопіювати `.env.example` у `.env` і вказати пароль та адресу бази даних у `DATABASE_URL`.
6. Створити таблиці:

   ```powershell
   python -m backend.database.init_db
   ```

7. Запустити сервер із кореня репозиторію:

   ```powershell
   uvicorn backend.main:app --reload
   ```

8. Відкрити:
   - Вебінтерфейс: http://127.0.0.1:8000/
   - Документація API: http://127.0.0.1:8000/docs
   - Перевірка стану: http://127.0.0.1:8000/health

## Основні API-операції

| Метод | Шлях | Призначення |
|---|---|---|
| GET, POST | `/api/suppliers` | Перегляд і створення постачальників |
| GET, PUT, DELETE | `/api/suppliers/{id}` | Отримання, редагування та видалення постачальника |
| GET, POST | `/api/products` | Перегляд і створення товарів |
| PUT, DELETE | `/api/products/{id}` | Редагування та видалення товару |
| GET, POST | `/api/deliveries` | Перегляд і реєстрація поставок |
| PUT, DELETE | `/api/deliveries/{id}` | Редагування та видалення поставки |
| GET | `/api/deliveries/export.csv` | Експорт поставок у CSV |

## Тестування

Після встановлення залежностей виконати:

```powershell
pytest -q
```

Тести використовують тимчасову SQLite-базу, тому для їх запуску не потрібно підключатися до робочої PostgreSQL.

## Безпека

Не зберігайте реальні токени, паролі чи ключі API в репозиторії. Для локального запуску використовуйте файл `.env`, який не додається до Git. Раніше опубліковані ключі OpenRouter і токен Telegram потрібно відкликати та створити нові до розгортання проєкту.

## Стан реалізації

На поточному етапі реалізовано початкову схему даних, CRUD API для основних сутностей, CSV-експорт і базовий вебінтерфейс. Базовий webhook Telegram і обробка голосових повідомлень додані в гілці cloud-migration. Перед реальною експлуатацією ще потрібно перевірити інтеграцію з активними токенами, реалізувати CRUD-команди бота, автентифікацію вебінтерфейсу, міграції Alembic, хмарне розгортання та вимірювання продуктивності.

## Голосовий режим

Вебсторінка записує голос через MediaRecorder і надсилає його на `POST /api/assistant/voice`. Сервер розпізнає українське мовлення через Groq Whisper, формує відповідь через OpenRouter і озвучує її за допомогою gTTS.

Для роботи голосового режиму додайте до локального файлу `.env`:

- `GROQ_API_KEY` — ключ сервісу розпізнавання мовлення.
- `OPENROUTER_API_KEY` — ключ сервісу генерації відповідей.

Браузер повинен мати дозвіл на використання мікрофона. Для розміщеного сайту потрібен HTTPS; під час локальної розробки допускається localhost.

Доступні маршрути:
- `POST /api/assistant/chat` — текстове повідомлення помічнику.
- `POST /api/assistant/voice` — аудіофайл у полі `file` (multipart/form-data).

**Поточне обмеження:** голосова команда наразі розпізнається й отримує відповідь від ШІ, але ще не виконує фактичні операції в таблицях бази даних. Наступний етап — контрольоване перетворення команд на CRUD-дії з перевіркою параметрів і підтвердженням користувача. Також необхідно провести вимірювання точності розпізнавання, затримки та стабільності.


## Підключення Telegram webhook

1. Створіть бота через BotFather і додайте новий токен лише у локальний `.env` або змінні середовища хостингу.
2. Згенеруйте окремий секрет webhook (1–256 символів; літери, цифри, дефіс або підкреслення) і задайте `TELEGRAM_WEBHOOK_SECRET`.
3. Після розгортання API на HTTPS встановіть webhook, підставивши власні значення:

   ```bash
   curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
     -d "url=<APP_BASE_URL>/api/telegram/webhook" \
     -d "secret_token=<TELEGRAM_WEBHOOK_SECRET>"
   ```

4. Надішліть боту текстове повідомлення або голосове повідомлення. Голосовий запит потребує налаштованого `GROQ_API_KEY`; відповідь ШІ — `OPENROUTER_API_KEY`.

Webhook перевіряє заголовок `X-Telegram-Bot-Api-Secret-Token`. Не використовуйте старі токени, які могли потрапити до історії Git; відкличте їх у відповідних сервісах і створіть нові.


## Команди обліку в Telegram

Після підключення webhook бот підтримує прямі команди до спільної PostgreSQL-бази:

| Команда | Дія |
|---|---|
| `/suppliers` | Переглянути постачальників |
| `/products` | Переглянути товари |
| `/deliveries` | Переглянути останні поставки |
| `/supplier_add Назва|Контакт|Телефон|Email` | Додати постачальника |
| `/supplier_edit ID|Назва|Контакт|Телефон|Email` | Оновити постачальника |
| `/supplier_delete ID ПІДТВЕРДЖУЮ` | Видалити постачальника |
| `/product_add Назва|Одиниця|Опис|Ціна` | Додати товар |
| `/product_edit ID|Назва|Одиниця|Опис|Ціна` | Оновити товар |
| `/product_delete ID ПІДТВЕРДЖУЮ` | Видалити товар |
| `/delivery_add ID_постачальника|ID_товару|Кількість|РРРР-ММ-ДД|Ціна|Примітки` | Зареєструвати поставку |
| `/delivery_edit ID|ID_постачальника|ID_товару|Кількість|РРРР-ММ-ДД|Ціна|Примітки` | Оновити поставку |
| `/delivery_delete ID ПІДТВЕРДЖУЮ` | Видалити поставку |

Порожні необов'язкові поля залишайте порожніми між роздільниками `|`.
Наприклад: `/supplier_add ТОВ Альфа|Іван|+380501112233|alpha@example.com`.

Видалення постачальника або товару заборонене, якщо на нього посилаються записи поставок. Для будь-якого видалення потрібне точне підтвердження `ПІДТВЕРДЖУЮ`. Голосом доступні запити на перегляд списків і диктування команди додавання у форматі з роздільниками `|`.

Команди реалізовані окремим сервісом `backend/services/telegram_commands.py`; обробник webhook передає їх у цей сервіс, а він виконує перевірені операції через SQLAlchemy. Текстові та голосові звернення, які не є командами обліку, як і раніше передаються до мовної моделі.
